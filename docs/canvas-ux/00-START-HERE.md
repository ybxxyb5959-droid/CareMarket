# Gemini Canvas 전달 안내

이 패키지는 현재 CareMarket의 **화면 + 사용자 행동 + 상태 변화**를 설명한다. 기존 코드의 기능을 바꾸지 않고 분석한 자료다.

## 파일

1. `01-UX-SPEC.md` — A~J 전체 명세. 먼저 전달한다.
2. `02-FRONTEND-CODE.md` — 63개 프론트 파일의 관련 코드. 필요한 화면의 섹션을 추가 전달한다. 각 발췌에 원본 경로·줄번호가 있다.
3. `03-index.css` — 원본 스타일 전체. 누적된 override 순서를 보존했으며, 과거 미사용 클래스도 포함될 수 있다.
4. `04-SOURCE-MANIFEST.json` — 출처 파일·발췌 범위·SHA-256. 검증/추적용이며 Canvas에 필수로 전달할 필요는 없다.

ZIP은 파일 묶음 전달용이다. Canvas에서 ZIP을 읽지 못하면 압축을 풀어 위 파일을 개별 첨부하거나 내용을 붙여넣는다. 코드와 CSS를 한 번에 붙여넣기 어렵다면 명세부터 전달하고 변경할 화면의 코드만 추가한다.

## Canvas에 붙여넣을 요청문

```text
첨부한 CareMarket UX 명세를 현재 서비스의 기준으로 읽어줘.
01-UX-SPEC.md의 A~J를 먼저 읽고, 02-FRONTEND-CODE.md의 해당 화면 코드와
03-index.css를 참고해 화면·사용자 행동·상태 변화의 관계를 이해해줘.

다음 원칙을 지켜줘.
- 화면 URL과 모달/Drawer/탭의 로컬 상태를 구분한다.
- 구매 목적, 빠른 조건, 알레르기 설정과 임시 숨김 OFF를 구분한다.
- 상품 담기는 토스트를 표시하며 Drawer 자동 열기가 아니다.
- 상품 상세 구매 CTA는 장바구니 확인으로 연결된다.
- Cart AI는 기본 분석과 사용자가 요청하는 AI 설명을 구분하고 상품 종류 기준을 유지한다.
- 로그인/미로그인/목적 미설정/알레르기/장바구니/쿠폰/관리자별 분기를 유지한다.
- 로딩·빈 결과·실패·재시도·저장 중·결제 대기 상태를 정상 화면과 함께 고려한다.
- 미구현 표시가 있는 기능을 완성된 기능으로 해석하지 않는다.
- 코드 발췌는 독립 실행 프로젝트가 아니다. 서버·DB·실제 계정·결제 연결은 재현 대상이 아니다.
- 프로토타입이 필요하면 비식별 가상 데이터로 상태를 재현한다.
- 모바일 개선 제안은 J를 참고하되, 현행 동작과 개선안을 명시적으로 구분한다.

우선 전체 화면과 핵심 구매 흐름을 이해한 뒤, 내가 지정하는 화면의 디자인 작업에 적용해줘.
```

## 해석 우선순위

현재 동작은 명세와 JSX 이벤트/조건으로 확인하고, 시각 스타일은 실제 렌더되는 JSX 클래스와 CSS cascade를 함께 확인한다. 코드 주석·샘플 문구·미사용 CSS만으로 기능을 추론하지 않는다.

이번 검증 범위는 소스 정적 분석, route 매핑 누락 확인, 발췌 원문 일치와 제외 대상 점검이다. 실제 로그인·AI·결제·브라우저 화면 검증은 수행하지 않았다. 원본 서비스 코드는 수정하지 않았다.

검증 결과: 정적 URL 매핑 32개와 전체 페이지 파일 27개를 포함했다. 검색 별칭·상품 상세 동적 URL·쿠폰 hash·관리자 query도 명세에 별도 기술했다. 코드 출처 63개 파일의 해시가 현재 원본과 일치하며 CSS는 원본과 바이트 단위로 동일하다. 발췌 코드에 DB 쿼리·직접 인증 구현·환경변수 참조·명백한 비밀키 형식이 없는지 점검했다.
