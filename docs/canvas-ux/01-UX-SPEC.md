# CareMarket 프론트엔드 UX 명세

기준: 2026-09-07, 현재 작업 디렉터리의 수정 중인 프론트엔드 코드 포함. 배포본이나 과거 스크린샷이 아닌 현재 소스 기준이다. 코드를 정적으로 분석했으며 실제 로그인·결제·AI 응답 성공이나 브라우저별 렌더링을 검증한 문서는 아니다.

Canvas 전달 순서: 이 문서 → 필요한 화면의 `02-FRONTEND-CODE.md` → `03-index.css`. 코드 발췌는 디자인·행동 이해용이며 독립 실행 앱이 아니다. 서버 구현, DB 쿼리/스키마, 테스트, 환경설정 값, 실제 회원·주문 데이터는 패키지에서 제외한다.

## A. 서비스 개요

CareMarket은 구매 목적과 영양·알레르기 조건으로 건강식품을 탐색하고 비교·주문하는 커머스다. 핵심 경험은 **목적 선택 → 조건에 맞는 상품 발견 → 표시 정보 확인 → 장바구니 구성 분석 → 주문·결제**다.

- 목적 4개: 근육량 증가 / 체중 관리 / 식단 영양 관리 / 영양제 탐색.
- 보조 조건: 저당(당류 ≤5g), 저염(나트륨 ≤250mg), 고단백(단백질 ≥15g), 카페인 제외. 등록된 1회 제공량 정보에 적용하는 내부 탐색 기준이다.
- 알레르기 설정: 대두·우유·계란·견과류·밀·갑각류·복숭아·쇠고기·닭고기. 등록 성분과 일치 여부를 확인한다. 미표시 성분까지 안전하다고 판단하는 기능은 아니다.
- 기본 배송비 3,000원, 상품금액 40,000원 이상 무료배송. 쿠폰은 주문서에서 적용한다.
- 상품 추천 순위·카드 영양 강조·상세 조건 일치 판정은 로컬 규칙이다. 자연어 검색 조건 해석, 비교 설명, 장바구니 설명 보완이 외부 AI 요청을 사용하는 기능이다.
- 스타일: 따뜻한 종이색 배경, 흰 패널, 짙은 숲색 CTA, 세이지색 보조 면, 얇은 구분선, 큰 상품 이미지. 제목의 serif와 본문의 sans를 함께 사용한다.

**URL과 화면 상태의 경계**

- 카탈로그 URL은 `q`, `mode=ai`, `category`, `sub`, `deals=1`, `sort`를 표현한다. 검색어가 있으면 `/search`, 없으면 `/products`를 생성한다. `/products?q=…`도 읽지만 카탈로그 동기화 과정에서 `/search`로 정리된다.
- 일반 정렬: `recommend`, `lowPrice`, `highPrice`; AI 모드 추가 정렬: `protein`, `sugar`, `sodium`.
- 빠른 조건, 구매 목적, 알레르기 숨김 OFF, 비교 선택, 탭·접힘 상태는 URL에 없다. URL 공유만으로 동일 화면 상태 전체를 복원할 수 없다.
- `navigate`/`openProduct`는 현재 스크롤을 기록하고 새 화면 상단으로 이동한다. 뒤로/앞으로는 URL의 카탈로그 조건과 저장된 스크롤을 복원한다. Drawer·모달 열기는 URL을 바꾸지 않는다.
- AI URL 직접 진입/새로고침은 `aiQuery`만 복원한다. AI 결과를 자동 재요청하지 않으므로 예시/입력 대기 UI가 나올 수 있다. 브라우저 뒤로가기에서도 URL과 메모리의 AI 결과가 항상 맞는다고 가정하지 않는다.
- 일반 전체상품 링크는 AI 모드를 종료한다. `navigateToCatalog`는 일반 검색·AI·빠른 조건·특가·정렬을 초기화하고 선택한 대/소분류를 설정한다. 반면 단순 `navigate('products')`는 기존 일반 검색/분류/빠른 조건을 모두 지우는 함수가 아니다.
- 모든 소비자 화면에 Header/Footer. 관리자 view에서는 AdminTopbar로 대체하고 Footer를 숨긴다. 관리자 URL 직접 진입 시에는 AdminGate가 로그인/권한 안내를 표시한다.

## C. 사용자 플로우

### C1. 상품 발견에서 결제까지

```text
홈 / 카테고리 / 검색 / 맞춤 추천 / 특가 / 베스트 / 신상품
  → 상품 카드 → 상품 상세
  → 수량 선택 → 장바구니 담기
  → 성공 토스트 ‘장바구니 보기’ 또는 헤더 장바구니 클릭
  → 장바구니 Drawer [수량·삭제·경고·AI 분석]
     ├─ 상세 보기 → /cart [전체 금액·목적 분석·구성 보완]
     │               → 주문하기 → /checkout
     └─ 주문하기 → /checkout (장바구니 상세 생략 가능)
  → 배송지 확인/수정 → 쿠폰 선택 후 적용 → 결제수단·필수 약관
  → 결제하기 → 금액 확인 → 외부 결제 흐름
     ├─ /payment/success → 승인 확인 중
     │   ├─ 승인 완료 → 장바구니·상품 다시 조회 → 주문내역
     │   ├─ 결제 대기 → 아직 주문 미확정 안내 → 장바구니
     │   └─ 확인 오류 → 다시 확인 / 장바구니
     └─ /payment/fail → 장바구니 유지 → 다시 결제 / 장바구니
```

상세의 **‘장바구니에서 구매하기’**는 선택 수량을 저장한 다음 `/cart`로 이동한다. 단품 주문서로 바로 이동하지 않는다. 일반 담기는 성공 토스트만 띄우며 Drawer를 자동으로 열지 않는다. 장바구니에는 선택구매 체크박스가 없고 담긴 모든 활성 상품을 주문한다.

### C2. 비회원 → 가입 → 맞춤 설정

```text
비회원 탐색 → 담기/장바구니 클릭 → 로그인 필요 dialog
  ├─ 더 둘러보기 / 닫기 → 원래 화면 유지
  └─ 로그인 → 이메일 로그인 성공 → 홈
               └─ 회원가입 → 약관 동의 → 회원정보 입력
                   ├─ 즉시 세션 발급 → /goals → 저장 → /for-you
                   └─ 이메일 인증 필요 → /login + 인증메일 안내

Google/카카오 인증 → 프로필 확인
  ├─ 가입 정보 완성 → 일반 서비스
  └─ 추가 가입 필요 → 현재 URL과 무관하게 Register 표시
      → 필수 약관·배송정보 입력 → 가입 완료 → 홈
```

로그인 전에 시도한 담기·찜을 자동 재실행하거나 원래 상품으로 자동 복귀하는 흐름은 없다. 비회원 홈 목적 선택은 추천을 즉시 바꾸는 체험이며 영구 저장은 아니다.

### C3. 목적·조건·알레르기

```text
/goals → 구매 목적 1개 → 보조 조건 여러 개 → 제외 성분 여러 개
  → 클릭 즉시 전역 goal/subFilters/allergies 변경
  → 저장 CTA → 저장 중 → 성공 → /for-you
  → 추천 상품 / 전체상품 → 빠른 조건·정렬 조정
  → 알레르기 숨김 기본 ON → 해당 성분 상품 제외
  → 사용자가 숨김 OFF → 다른 조건을 통과한 해당 상품만 다시 노출
  → 카드 ‘⚠ 성분 포함’ → 상세 경고 → 원재료 탭 확인
  → 담기 가능 → Drawer·Cart·분석 결과에서도 경고 유지
```

숨김 OFF는 제외 성분 삭제나 안전 판정이 아니다. 상세와 장바구니는 경고를 표시하지만 경고 확인 동의나 구매 차단을 요구하지 않는다. AI 검색에서 사용자가 지정한 별도 제외 성분은 숨김 OFF 이후에도 필터링한다.

### C4. 탐색 보완과 재구매 접점

```text
자연어 입력 → 해석된 조건·결과 → 빠른 조건/정렬 → 상품 2~3개 선택
  → 로그인 상태에서 비교 → 수치표 + AI 비교 설명 → 닫고 목록 계속

Cart → 기본 목적 분석 → 필요 시 AI 설명 요청 → 보완 상품 CTA
  → 카테고리·빠른 조건이 적용된 목록 → 상품 추가 → Cart에서 새 구성 확인

MyPage → 최근 주문 / 전체 주문 → 배송 상태·주문 상세 펼치기
MyPage → 찜 목록 → 담기 또는 상세 → 주문 흐름
FAQ → 문의 작성 → 접수 완료 → 문의내역 → 답변 확인
```

## D. 화면별 인터랙션 명세

표의 ‘변화’는 사용자에게 보이는 결과와 연결된 상태를 함께 적었다. 로컬 state는 기본적으로 해당 페이지가 언마운트되면 초기화된다. 공통 오류 상태는 빈 결과와 분리하며, 실제 구현에 있는 재시도 버튼만 제공한다.

### D1. 공통 Header / Footer / 전역 레이어

| 요소 / 행동 | 변화·이동·조건 |
|---|---|
| 로고 | `/` 이동 |
| 일반 검색 입력 | `searchInput` 초안; 입력만으로 결과 목록 확정 안 됨. 포커스·문자열 존재 시 검색 버튼 표시 |
| 자동완성 | 1자 이상 입력 시 실제 상품 기반 검색어 최대 5개·관련 상품 최대 3개. 검색어 선택→목록, 상품 선택→상세. 방향키/Enter 선택, Escape 닫기 |
| 일반 검색 제출 | 초안을 trim하여 `search` 반영, 목록 이동, 특가 OFF, 자동완성·모바일 검색 닫기 |
| AI/일반 전환 | AI 진입 시 `searchMode='ai'`, 일반 검색어 초기화. 일반 복귀는 진행 요청·AI 결과·오류·AI 전용 정렬 초기화 |
| AI 검색어 X | `aiQuery`만 비움. 기존 결과까지 제거하는 전체 초기화와 다름 |
| 일반 검색어 X | 입력 초안만 비움. 확정 검색 결과 삭제는 제출 또는 결과 칩 X로 수행 |
| 대/소분류 메뉴 | `navigateToCatalog`; 검색·빠른 조건 초기화 후 지정 분류로 이동. hover 드롭다운을 사용하므로 모바일 탭 접근성 확인 필요 |
| 특가 / 베스트·신상품 / 맞춤 상품 | 특가는 GNB, 베스트·신상품은 Footer, 맞춤은 상단 혜택 띠 등에서 각 route 이동 |

### D6. CartDrawer

- `drawerOpen`이 false면 렌더 없음. 열리면 overlay와 오른쪽 aside. overlay·X로 닫는다. 별도 URL과 뒤로가기 단계는 없다.
- 상품 이미지·이름은 Drawer에서 상세 링크가 아니다. 수량 −/+·삭제가 있고, 목적별 단백질/열량/나트륨과 알레르기 배지를 표시한다. 영양제 목적의 이미지 위 영양값은 생략한다.
- 수량은 최저 1, 재고 상한. 증가 버튼은 `cartPending` 중 비활성. 감소·삭제의 비활성 조건은 Cart 상세와 동일하지 않다.
- 비었으면 빈 안내. 로딩·실패 시 상태 문구와 다시 불러오기. 상품이 있을 때만 AI compact·금액·하단 CTA 표시.
- ‘장바구니 상세 보기’→닫고 `/cart`. ‘주문하기’→닫고 `/checkout`, 로딩·저장 중·오류면 disabled.
- AI 기본은 분석 버튼만 표시. 분석 성공/기본 fallback 이후 요약·구성 지표·보완 문구·자세히·다시 분석 표시.
- **현재 구현 한계:** Drawer에는 Escape 핸들러, focus trap, 열릴 때 body 스크롤 잠금이 없다. 모바일 bottom sheet나 드래그 닫기를 이미 구현한 것으로 해석하지 않는다.

### D7. Cart 상세

- 주문 상품 → 주문 금액 → AI 목적 분석으로 구성. 데스크톱은 왼쪽 상품/분석, 오른쪽 금액; 모바일은 세로 흐름.
- 4종 이상이면 첫 3종만 노출, ‘나머지 N종 더 보기’/‘상품 접기’로 `productsExpanded` 전환. 금액과 분석은 숨겨진 상품도 포함한다.
- 수량 변경→로컬 `optimisticQuantities`로 숫자·합계 즉시 표시→저장 완료 시 실제 상태로 정리. 실패 결과도 실제 장바구니 상태로 돌아간다. 삭제는 별도 확인창 없이 저장 요청.
- 이미지/상품명→상세. 알레르기 배지와 목적별 영양값은 각각 표시.
- 상품금액·배송비·무료배송까지 남은 금액·예상 결제금액. 저장 중 ‘금액 반영 중…’. 주문은 로딩·저장 중·오류면 disabled.
- 분석은 먼저 기본 규칙 결과를 보여준다. ‘AI 한눈 요약’, 핵심 지표(최대 기본 3개+확인 필요), 좋은 점/확인할 점, 상품별 분석, 보완 CTA 순서. 추가 지표·상품 근거는 `details` 펼침.
- ‘장바구니 영양 분석하기’/‘다시 분석’→AI 요청; 구성 변경 시 기본 분석으로 전환하고 다시 분석 안내. 분석 실패가 주문을 막지 않는다.
- 보완 상품 CTA는 추천 결과에 있을 때만 표시. 전체상품 또는 영양제 카테고리로 이동한 뒤 추천 빠른 조건을 설정한다.
- 빈 장바구니→상품 둘러보기, 오류→재시도. 비회원 `/cart` 직접 진입은 별도 로그인 페이지 대신 비어 있는 장바구니로 보일 수 있다.

| 승인 성공 URL | 곧바로 성공 표시하지 않음. 인증 후 승인 확인. 완료 확인 시만 성공·주문번호·금액과 주문내역 CTA |
| 승인 대기/오류 | 대기: 미확정 안내. 오류: 다시 확인하기. 비회원: 로그인 필요. 로그인 후 결제 콜백으로 자동 복귀하는 로직은 없음 |
| 결제 실패 URL | 취소/문제 안내, 상품 유지, 장바구니 복귀·다시 결제 |
| Orders | 결제완료/상품준비중/배송중/배송완료 배지, 주문 당시 가격·수량. 주문 상세 `details`로 수취인·주소·요청사항 펼침 |
| Orders 예외 | 로그인 필요·로딩·조회 오류+재시도·주문 없음+상품 둘러보기. 취소/반품 신청·재구매 버튼 없음 |

현재 결제 위젯 초기화는 테스트용 키 형식일 때만 진행한다. 실제 운영 결제 지원까지 완성됐다고 판단하지 않는다. 쿠폰 UI는 응답의 할인율을 표시하지만 주문서의 예상 할인 계산은 현재 **상품금액의 20% 내림**으로 고정되어 있다. 배송비에는 할인이 적용되지 않는다.

### D10. 서비스 안내 / 고객지원 / 제휴 / 404

- ServiceInfo는 `view`에 따라 제목·본문·CTA를 바꾼다. 소개→원칙→제휴→제안서로 연결. 약관/개인정보/클린라벨은 읽기 중심이며 홈 복귀 제공.
- Support: FAQ 검색은 입력 즉시 로컬 문자열 검색. 분류 버튼은 검색어와 열린 답변 초기화. 질문 클릭은 한 개씩 펼침/접힘. 검색 없음 안내에 문의 CTA. AI 챗봇이 아니다.
- SupportInquiry: 로그인 보호. 작성/작성내역 탭은 동일 route의 로컬 `mode` 변경. 내역 탭 재진입 시 재조회. 폼은 문의유형·제목(160자)·내용(4,000자)·답변 이메일·개인정보 동의, 선택 주문번호. 검증 오류는 첫 필드로 focus. 주문 조회 실패 시 주문번호 선택 비활성, 본문에 적도록 안내. 제출 중 중복 방지, 실패 시 입력 유지; 성공은 접수번호·내 문의/FAQ CTA.
- 문의 탭 전환은 작성 컴포넌트를 언마운트하므로 작성 초안/접수 결과를 보존하지 않는다. 내장 작성내역의 상세는 `showDetailBack=false`이므로 단독 내역 화면과 동일한 뒤로 버튼을 기대하면 안 된다.
- SupportInquiries: 전체/답변대기/완료 개수, 행/제목 클릭→로컬 상세, 답변 또는 대기 안내. 단독 화면은 목록 복귀 제공. 상세 route는 따로 없다. 로딩·재시도·문의 없음 CTA.
- PartnerProposal: 비회원도 작성 가능. 브랜드/담당자/이메일/제안유형/카테고리/브랜드 소개/동의 필수; 연락처/홈페이지/대표상품/제휴 이유 선택. 검증 시 첫 오류 focus, 제출 중 disabled. 실패 입력 유지, 성공 폼 대신 접수 완료+홈 CTA. 안내 복귀는 `/partners`.
- NotFound: 404·안내·홈/전체상품 CTA. 상품 미존재는 이 화면 대신 ProductDetail 자체 예외 UI를 쓴다.

### D11. 관리자 화면

모든 관리자 페이지는 AdminGate 사용. 인증/프로필 확인 중→권한 로딩, 비회원→로그인, 일반회원→권한 안내·상품 둘러보기. 소비자 UI에서 `navigate`로 관리자 접근 시도는 홈 이동+권한 토스트. 관리자 프로필 확인 시 소비자 URL은 대시보드로 전환될 수 있으나 결제 콜백은 제외한다.

| 화면 | 행동 → 상태 / UI |
|---|---|
| 공통 AdminTopbar | 대시보드·상품·주문·협업·문의 전환, 스토어 보기→홈, 로그아웃 |

## F. AI 기능 흐름

### F1. 자연어 검색 — 연결됨

- **트리거:** Header AI 모드에서 제출 또는 AllProducts 예시 클릭. 모드 전환 자체는 호출하지 않는다. 비회원 UI에서도 사용 가능.
- **입력:** 사용자가 쓴 문장, 최대 250자. 예: ‘당류 낮고 단백질 높은 간식 찾아줘’. 빈/잘못된 입력은 검증 오류.
- **진행:** 이전 요청 취소 → `aiLoading=true`, 기존 결과/오류 지움 → 상품 목록 이동 → ‘검색 조건을 정리하고 있어요’. 요청 제한 시간 18초.
- **결과:** 카테고리·단백질 최소·당류/나트륨/열량/가격 최대·카페인 제외·알레르기 제외·키워드·정렬 조건. 원문과 해석 칩, 조건에 맞는 실제 상품·개수를 표시한다.
- **적용:** 기존 카테고리/빠른 조건/개인 알레르기로 1차 필터 후 AI 조건을 AND 적용. 자연어가 기존 카테고리와 충돌하면 결과가 없을 수 있다. AI 반환값을 상품 목록 자체로 표시하지 않는다.
- **실패 fallback:** 이전 결과를 숨기고 오류+다시 시도+일반 검색 전환. 임의 추천이나 자동 일반 검색 대체는 없다.
- **중요:** AI가 정렬을 선택한 후 사용자가 정렬을 바꿀 수 있다. 전체상품 일반 진입은 AI 상태를 종료한다. URL 새로고침 자동 재검색은 미구현.
- 자연어 결과의 수치 조건은 반환된 조건 칩을 따른다. 브라우저가 참조하는 공용 검색 계약은 AI용 저당 기준을 2g으로 두고 있어, 수동 빠른 조건의 5g과 동일하다고 가정하면 안 된다. 서버 구현은 패키지에 포함하지 않는다.

### F2. 상품 비교 — 연결됨

- **트리거:** AllProducts에서 2~3개 선택→회원이 비교하기→모달 mount 시 자동 요청.
- **입력:** 선택 상품 ID 배열. 별도 자연어 입력창 없음. 요청 본문에는 로컬 `goal`을 직접 보내지 않으며 모달 제목에는 현재 로컬 목적을 표시한다.
- **진행/결과:** 가격·열량·단백질·탄수화물·지방·당류·나트륨·알레르기·카페인 표는 즉시 표시. 하단은 AI 로딩→비교 요약·상품별 특징·목적 적합 설명·추천 상품과 이유.
- **실패 fallback:** 실제 수치표는 유지. AI 영역만 오류+재시도. 로컬 추천 문장 생성 없음.
- **닫기:** X·배경·Escape, 요청 취소·body 스크롤 복원. ≤720px에서는 아래에 붙는 sheet 모양이지만 드래그 제스처는 없다.
- **주의:** 제목의 로컬 목적과 응답이 사용한 저장 목적이 같은지 이 컴포넌트는 검증하지 않는다. Cart와 다른 점이다.

### F3. AI 장바구니 목적 분석 — 연결됨

| 단계 | 상세 Cart | compact Drawer |
|---|---|---|
| 진입/idle | 등록 정보 기반 기본 분석을 즉시 표시 | AI 설명 안내와 분석 버튼 |
| 사용자 입력 | 자유문장 없음. 현재 담긴 상품, 목적, 빠른 조건, 제외 성분이 분석 맥락 | 동일 |
| 요청 | 하단 분석/다시 분석 클릭 때만 `cart_summary` 요청 | AI 분석하기 클릭 |
| loading | 현재 기본 분석은 유지, 버튼 ‘분석 중…’ | disabled 로딩 버튼 |
| success | 요약·기준 충족 상품 수·좋은 점/확인할 점·상품별 근거·보완 CTA | 요약 지표·설명·자세히/다시 분석 |
| 실패 | 기본 분석을 success 형태로 사용, 기본 분석/설명 제한 안내 | 기본 분석 결과를 표시 |
| 구성 변경 | 새 로컬 기본 분석+변경 안내, 사용자가 재요청 | stale 안내+다시 분석 |

- 분석 단위는 **상품 종류**, 실제 섭취량이나 수량 곱 영양 총량이 아니다. 수량만 변경하면 금액은 바뀌지만 분석 key는 유지된다.
- key 구성: 계정, 목적, 정렬된 보조 조건/알레르기, 상품 ID·영양·성분·카테고리. 상품 추가/삭제나 목적·조건 변화는 분석을 오래된 결과로 본다. 저장 중·조회 오류·빈 장바구니·설정 로딩 중은 요청 불가.
- 최초 기본 결과도 AI 영역에 표시되므로 ‘AI 한눈 요약’ 제목만 보고 외부 생성 완료로 판단하면 안 된다. `aiExplanationAvailable`로 생성 설명/기본 설명 구분.
- 응답의 분석 기준과 현재 로컬 기준이 다르면 로컬 기본 분석을 사용한다. API 오류·시간초과에도 상품 정보와 경고를 유지한다.
- 같은 key의 응답은 메모리 캐시 재사용, 같은 key 요청은 공유. 다른 분석 요청은 이전 요청을 취소하고 늦게 온 결과가 새 화면을 덮지 않도록 처리한다.
- 보완 CTA는 상품을 자동으로 장바구니에 추가하지 않는다. 조건이 적용된 목록으로 이동하여 사용자가 다시 고른다.

### F4. AI 조건 추천 — 현재 UI 미연결

`src/lib/ai-filter-recommendation.js`에 입력 검증·결과 캐시·오류 메시지·18초 제한을 갖춘 요청 함수가 있다. 그러나 현재 `src`의 화면/컴포넌트에서 이 함수를 호출하는 곳은 없다. 따라서 ‘목적 선택하면 AI가 빠른 조건을 자동 선택한다’는 사용자 흐름은 현재 기능이 아니다. AllProducts는 이 기능의 공용 계약 중 카테고리별 **표시 가능한 필터 ID**만 참조한다.

### F5. AI로 오해하면 안 되는 기능

홈/맞춤 추천 순위, GoalBadge, 상세 조건 일치, DailyRoutine, WellnessTable, 특가 선정, FAQ 검색은 프론트 규칙/설정 콘텐츠이다. sparkles 아이콘이나 ‘분석’이라는 단어가 있어도 외부 AI 호출을 의미하지 않는다.

## J. 모바일 UX 개선 시 주의점

다음은 **개선 제안 및 보존 조건**이며 현재 구현과 구분한다.

1. **경고와 숨김을 분리한다.** OFF여도 제외 성분 설정은 보존하고 카드→상세→Drawer→Cart 경고를 유지한다. 현재 미적용인 히어로/특가/테이블/자동완성에 적용 범위를 확장한다면 동작 변경으로 명시한다. 주문서에는 현재 별도 알레르기 배지가 없다.
2. **금액과 분석 단위를 섞지 않는다.** 수량은 금액·배송에 반영, 분석은 상품 종류 기준. 장바구니 분석을 실제 하루 섭취량 또는 건강 진단처럼 바꾸지 않는다. 추천/카드 설명과 실제 표시 지표의 차이(식이섬유 문구 등)도 먼저 정리한다.
3. **주문 CTA 의미를 보존한다.** 상세 CTA는 장바구니 확인, Cart CTA는 주문서, Checkout CTA는 결제 요청이다. 모바일 고정 바도 같은 함수·pending·재고·금액을 사용한다.
4. **고정 UI 겹침을 점검한다.** 상세/Cart/Checkout 하단 바, 토스트, Drawer footer, 가상 키보드, iOS safe-area. 본문 끝과 마지막 버튼까지 스크롤할 여유를 유지한다.
5. **레이어 접근성을 개선한다.** Drawer의 Escape·focus trap·스크롤 잠금/포커스 복원을 추가 검토. 비교 sheet는 스와이프가 없는 상태이며 추가 시 임계값·오동작 방지를 정의한다. 일부 카드 제목·이미지·목적 선택이 클릭 가능한 div/h3이므로 키보드 동작을 보완한다.
6. **선택 상태를 계속 보이게 한다.** 가로 스크롤 필터의 선택 개수·초기화·알레르기 ON/OFF를 숨기지 않는다. 비교 2~3개 선택은 스크롤/필터 후에도 알아볼 수 있도록 선택 상품 목록·해제 동선을 검토한다.
7. **URL 복원을 과장하지 않는다.** 검색 초안과 확정값, AI 조건과 결과, 로컬 필터와 저장 설정은 별개다. 뒤로가기/새로고침에서 AI 재요청 정책·설정 미저장 정책을 먼저 정의한다. ‘전체 초기화’의 실제 범위를 UI 문구와 맞춘다.
8. **회원가입·배송 입력의 손실을 줄인다.** 설정은 즉시 전역 변경, 문의 탭은 초안을 잃음, 배송 ‘동일’ OFF는 입력값을 비움. 모바일 재배치만으로 이런 동작을 바꾸지 말고 개선 여부를 따로 결정한다. 주소 조회 실패 시 우편번호 readOnly인 가입/MyPage 경로도 점검한다.
9. **AI 실패 상태를 보존한다.** 검색 오류와 결과 없음은 다르다. 비교는 수치표, Cart는 기본 분석을 계속 제공. 실제 호출 전에는 생성 AI가 완료된 것처럼 보이지 않도록 라벨을 구분한다.
10. **구현되지 않은 행동을 완성된 것처럼 디자인하지 않는다.** 탈퇴 실제 처리·비밀번호 찾기·네이버/애플 인증·AI 자동 조건 추천·운영 결제·주문취소/반품 신청은 현행 UI만으로 완성 기능이 아니다.
11. **반응형을 대표 상태로 검수한다.** 360/390/480/720/768/900/1080/1440px에서 긴 한국어 상품명, 여러 알레르기, 0/1/4종 Cart, 품절, 큰 금액, AI 로딩/기본 분석/변경, 쿠폰 없음/적용, 배송지 미완성, 로그인/OAuth 보완, 관리자 표/편집을 확인한다. 이는 후속 검수 제안이지 이번 실행 결과가 아니다.

Canvas가 재구성할 때는 B의 route와 C의 분기를 먼저 만들고, D/E의 조건부 상태를 구현한 뒤 I의 레이아웃을 적용한다. 개선안은 J에서 선택한 항목만 별도 변경으로 표시한다.
