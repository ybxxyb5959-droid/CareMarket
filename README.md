# CareMarket

**구매 목적에 맞는 상품을 찾고, 영양정보를 비교한 뒤 주문하는 웰니스 쇼핑몰입니다.**

“당류는 낮고 단백질은 높은 간식이 있을까?”라는 질문에서 시작해, 상품 검색 → 비교 → 장바구니 분석 → 결제 → 구매 후기까지 한곳에서 경험할 수 있습니다.

[서비스 바로가기](https://caremarket.vercel.app/) · [주요 기능](#주요-기능) · [로컬 실행](#로컬-실행)

> 포트폴리오·캡스톤 프로젝트입니다. 상품은 가상 데이터이며, 결제는 **Toss Payments 테스트 환경**을 사용합니다. 실제 판매·배송은 제공하지 않습니다. 아래 기능 설명은 현재 저장소 구현 기준입니다.

## 주요 기능

| 기능 | 사용자가 할 수 있는 일 |
| --- | --- |
| 목적별 쇼핑 | 근육량 증가·체중 관리·식단 영양 관리·영양제 탐색 중 구매 목적을 정하고, 관련 상품과 정보를 확인합니다. |
| 상품 검색·상세 필터 | 상품명·브랜드·카테고리를 검색하고, 저당·저염·고단백·카페인 제외 조건과 브랜드·최대 가격으로 결과를 좁힙니다. |
| AI 자연어 검색 | “당류 낮고 단백질 높은 간식”처럼 문장으로 입력하면 AI가 검색 조건을 정리하고 등록된 상품을 찾아줍니다. |
| 상품 비교 | 2~3개 상품의 가격·영양정보·알레르기·카페인 정보를 나란히 비교합니다. 로그인하면 일반 식품에 대한 AI 비교 설명도 확인할 수 있습니다. |
| 장바구니 영양 분석 | 담은 상품의 수량을 반영한 영양 합계와 구매 목적에 따른 분석을 확인합니다. 영양제는 일반 식품과 구분해 다룹니다. |
| 추천·할인 상품 탐색 | 오늘의 특가, 판매량 기준 베스트, 최신 등록 상품, 날짜에 따라 바뀌는 웰빙 테이블과 하루 루틴을 둘러봅니다. |
| 회원·개인 설정 | 이메일 회원가입·로그인, Google·카카오 간편로그인, 배송지·구매 목적·제외 조건 설정을 이용합니다. |
| 위시리스트·장바구니 | 관심 상품을 저장하고 계정별 장바구니에서 수량과 재고를 확인합니다. |
| 쿠폰·주문·결제 | 신규가입 20% 쿠폰과 조건을 충족한 첫 구매 리뷰 10% 쿠폰을 주문서에서 선택하고 테스트 결제를 진행합니다. |
| 구매 후기·신고 | 배송완료 상품의 리뷰를 작성·수정·삭제하고, 부적절한 후기를 신고합니다. |
| 고객지원·제휴 | FAQ를 검색하고 1:1 문의와 관리자 답변을 확인합니다. 브랜드 입점·제휴 제안도 접수할 수 있습니다. |

### 상품을 찾고 비교하는 방법

1. **구매 목적 선택** — 나에게 필요한 상품과 영양정보를 중심으로 탐색합니다.
2. **검색과 필터 적용** — 일반 검색 또는 AI 자연어 검색 후 카테고리·영양 조건·브랜드·최대 가격을 조합합니다. 적용된 상세 조건은 개별 해제하거나 초기화할 수 있습니다.
3. **상품 상세 확인** — 가격, 영양정보, 성분, 알레르기 정보와 후기를 확인합니다.
4. **비교 후 장바구니 담기** — 후보 상품을 나란히 비교하고, 담은 상품 전체의 영양 구성을 확인합니다.

일반 영양 필터의 기준은 **저당: 당류 5g 이하 / 저염: 나트륨 250mg 이하 / 고단백: 단백질 15g 이상**입니다. AI 검색에서 사용자가 수치를 직접 입력하면 해당 조건을 우선합니다. 미등록 영양정보는 0으로 간주하지 않고 **정보 없음**으로 표시합니다.

영양제 비교는 등록된 섭취 기준과 주요 성분을 중심으로 제공합니다. 일반 식품과 영양제를 같은 영양 점수로 평가하거나, 미등록 성분량을 추정하지 않습니다.

### 주문부터 리뷰 보상까지

```text
회원가입 → 신규가입 20% 쿠폰 발급
    ↓
상품 탐색 → 비교·장바구니 분석 → 배송정보 입력·쿠폰 선택
    ↓
Toss 테스트 결제 → 주문내역·배송 상태 확인 → 배송완료 후 리뷰 작성
    ↓
첫 구매 주문의 최초 리뷰라면 10% 쿠폰 지급 (계정당 1회)
```

| 항목 | 적용 기준 |
| --- | --- |
| 배송비 | 상품 합계 40,000원 이상 무료, 미만 3,000원 |
| 쿠폰 할인 | 선택한 쿠폰의 할인율을 상품금액에 적용하며 배송비는 제외 |
| 신규가입 쿠폰 | 신규 프로필 생성 시 20% 쿠폰 1장 자동 발급 |
| 리뷰 작성 | 본인의 배송완료 주문 상품에 별점 1~5점과 후기 20~1,000자 작성 |
| 리뷰 보상 | 첫 구매 주문에 작성한 최초 리뷰에 10% 쿠폰 지급, 별점과 관계없이 계정당 1회 |
| 첫 구매 기준 | 결제된 주문 중 결제일이 가장 빠른 주문. 과거 결제일 미기록 건은 주문 생성일로 판정 |
| 추가 리뷰 | 이후 배송완료 주문에도 리뷰 작성 가능. 보상은 추가 지급하지 않음 |
| 리뷰 수정·삭제 | 본인 리뷰만 가능. 삭제 후 재작성해도 쿠폰 중복 지급 없음 |

구매 확인 후기와 기본 표시용 샘플 후기는 구분합니다. 실제 리뷰 평균과 개수는 공개된 DB 리뷰만 집계하며, 숨김·삭제된 리뷰와 샘플 후기는 제외합니다.

## 최근 업데이트 — 2026-09-08

- **상세 필터 개선**: 브랜드·최대 가격 조건, 적용 조건 표시와 개별 해제·초기화 기능을 제공합니다.
- **리뷰 신고 추가**: 로그인 회원이 사유를 선택해 신고하고, ‘기타’ 선택 시 상세 내용을 입력합니다. 같은 회원의 동일 리뷰 중복 신고를 차단합니다.
- **관리자 신고 처리 추가**: 접수 대기·삭제 완료·리뷰 유지 상태별 조회와 대시보드 신고 현황을 제공합니다.
- **리뷰 보상 정책 정리**: 주문마다 지급하던 기준을 첫 구매 주문의 최초 리뷰, 계정당 1회로 제한했습니다. 리뷰 작성 가능 여부와 보상 대상을 분리했습니다.
- **리뷰·쿠폰 표시 수정**: 실제 리뷰 집계와 샘플 후기를 분리하고, 주문서에 선택한 쿠폰의 실제 이름을 표시합니다.
- **검색·영양정보 일관성 개선**: 일반 검색의 여러 단어를 함께 반영하고, 필터·AI 분석의 영양 기준과 미등록값 처리를 통일했습니다.
- **로그인·주문 조회 안정화**: 인증 후 원래 화면으로 복귀하며, 리뷰 정보 조회에 실패해도 주문내역은 표시합니다.

배포와 검증은 기능별로 진행되어 **저장소 구현 상태와 운영 반영 상태가 다를 수 있습니다.** 리뷰 보상 DB 사후 확인, 신고 기능 배포 및 남은 검증 범위는 아래 작업 기록에 따로 남겼습니다.

```text

 ├─ PostgreSQL + RLS               상품·회원·장바구니·주문·리뷰·문의

```

### 데이터와 결제를 처리하는 방식

- **AI 검색**: 서버가 AI 응답의 구조·허용값·수치를 검증하고 실제 등록 상품에 조건을 적용합니다. AI가 상품을 생성하지 않습니다.
- **AI 분석**: 서버에서 등록 영양정보를 합산하고 Gemini가 설명을 보완합니다. AI 응답 실패 시에도 가능한 계산 결과는 유지합니다.
- **접근 권한**: 개인 정보·장바구니·주문은 사용자 소유권으로 제한하고, 관리자 작업은 서버에서 권한을 다시 확인합니다.
- **결제 검증**: DB의 가격·재고·쿠폰을 기준으로 주문 금액을 계산하고 결제 승인 시 사용자·주문·금액을 검증합니다.
- **중복 처리 방지**: 재고 차감·장바구니 정리·쿠폰 사용을 같은 DB 트랜잭션으로 처리하며 동일 결제 재확인으로 중복 차감하지 않습니다.
- **결제 실패 대응**: 승인 후 확정적인 재고·금액 오류는 취소를 시도하고, 네트워크 오류로 결과가 불확실하면 상태 확인을 안내합니다.

## 로컬 실행

1. Vite 8을 지원하는 Node.js와 npm을 준비합니다.
2. 의존성을 설치합니다.

```bash
npm ci
```

3. `.env.example`을 참고해 `.env.local`을 작성합니다.

```dotenv
VITE_SUPABASE_URL=
VITE_SUPABASE_PUBLISHABLE_KEY=
VITE_TOSS_CLIENT_KEY=
```

4. 연결할 Supabase 프로젝트의 DB·인증 공급자·Edge Functions 설정을 확인합니다.
5. 개발 서버를 실행합니다.

```bash
npm run dev
```

프로덕션 빌드는 `npm run build`, 빌드 결과 확인은 `npm run preview`입니다. 산출물은 `dist/`에 생성됩니다.

<details>
<summary>서버 설정·배포 시 참고사항</summary>

- Edge Function 전용 비밀값: `GEMINI_API_KEY`, `TOSS_SECRET_KEY`(테스트 키). service role key와 비밀값은 브라우저 환경변수나 코드에 넣지 않습니다.
- 허용 origin 설정: `AI_SEARCH_ALLOWED_ORIGINS`, `AI_INSIGHTS_ALLOWED_ORIGINS`, `PAYMENT_ALLOWED_ORIGINS`. 추가 주소는 정확한 HTTPS origin을 쉼표로 구분합니다.
- `ai-insights`는 기본 운영 주소를 허용하고, 추가 주소는 `AI_INSIGHTS_ALLOWED_ORIGINS` 또는 대체 설정인 `AI_SEARCH_ALLOWED_ORIGINS`를 사용합니다.
- Edge Function 배포는 Vercel 프런트엔드 배포와 별개입니다. 예: `npx supabase functions deploy ai-insights --use-api`.
- 기존 운영 DB는 SQL 수동 적용과 migration 이력이 다를 수 있습니다. 아래 배포 기록을 확인한 뒤 필요한 변경만 반영하며, 전체 `supabase db push`나 상품 seed 전체 재실행을 하지 않습니다.
- 상품 이미지 manifest는 `dev`·`build` 실행 전에 자동 생성됩니다. 이미지 교체 시 파일과 `src/data/product-images.json`을 함께 커밋합니다.

</details>

테스트는 검색 조건, 영양 계산, 계정별 장바구니, 재고·결제 무결성, 리뷰 권한·보상·신고, 쿠폰 중복 사용 방지 등을 다룹니다. SQL 테스트는 별도 설치한 `@electric-sql/pglite`의 `dist/index.js` 절대 경로를 `PGLITE_MODULE`에 지정해야 실행되며, 미설정 시 해당 테스트는 건너뜁니다.

실제 OAuth 로그인, Toss 테스트 결제, 운영 DB와 브라우저 확인 결과는 자동 테스트와 구분해 작업 기록에 정리합니다.

## 프로젝트 범위

- 가상 상품의 가격·재고·영양정보를 사용하는 데모이며, 실제 구매 근거로 사용할 수 없습니다.
